## 2026-07-04
- **Data integrity fix (RentHelp backfill).** A deterministic CSV↔database reconciliation (multiset diff by `type | dates`, tolerant of the manual fleet split, restored Polish diacritics, and OCR look-alikes) found that the original migration — done visually in two passes — had silently dropped **30 of 82** RentHelp calendar rows. The source rows were present and valid in the export CSV (written 9h before `seed.sql`); they were simply left out by the by-eye curation, not a parse error and not added later. Most alarming: **5 of the missing entries were future/active blocks** ([klient 195] 07-16, [klient 361] Paszko's second Duster 08-16→30, [klient 908] 08-22, Paweł Witek 09-18, [klient 176] 09-19) — those vans showed as *free* in the app for dates RentHelp had blocked, a live double-booking risk. Backfilled all 32 missing entries (5 future blocks + 5 historical blocks + 22 historical reservations) plus 2 corrections (Paszko BPS82 end-date 08-25→08-30; the 2024 Pajero service moved from the Silver unit to the Blue unit per RentHelp) and removed a leftover test booking. Applied to production via the Management API and recorded idempotently (external_ref-guarded inserts, id-scoped updates/deletes) in `supabase/migrations/20260704120000_backfill_renthelp_missing.sql`, coherent with the seed→migrations replay (every backfilled reservation's customer already exists in `seed.sql`). Verified end-to-end: **82/82 CSV rows now reconcile, 0 missing**; the only DB surplus is the intentional split of the 2026 Pajero service across both physical Pajeros. Full method + tables: `docs/renthelp-reconciliation-2026-07-04.md`.
- **PWA install button on the login screen.** The "Zainstaluj aplikację" button now also appears on `/login`, not just inside the authenticated app shell — which is where it belongs for Android/desktop install, since an unauthenticated visitor lands on the login page first. Full-width secondary button below the sign-in card, shown only when the browser reports the app is installable (`beforeinstallprompt`); the service worker registers on `/login` too (via the always-mounted `AppShell`), so the install criteria are met there. Also dropped the `orientation: "portrait"` lock from `manifest.ts` so the installed window isn't forced portrait on a desktop.
- **Install button forces the native installer.** The "Zainstaluj aplikację" entry (left sidebar / mobile menu / login) calls the browser's own install prompt on click — `beforeinstallprompt` captured, `prompt()` fired on tap — so it opens the real native install dialog on Android/desktop Chrome & Edge, not a how-to. It appears only where the browser has armed that prompt (that event is the only mechanism a web page has to trigger installation — there is no unconditional "install now" API, and iOS Safari exposes none at all), and hides once the app is installed. The install event is captured at module load (before the button mounts), so a prompt Chrome fires early isn't missed and the button reliably shows whenever install is genuinely available. (Note: Chrome does not offer PWA install in Incognito/private mode — that's a browser rule, so testing there will always show the app without the button; use a normal tab on a device where it isn't already installed.)
