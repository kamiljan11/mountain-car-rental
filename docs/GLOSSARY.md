# GLOSSARY — domain dictionary (EN code / PL / context)

<!-- Names in code must come from here. A new term in a diff = a new row here. -->

| Term in code (EN) | PL | Meaning / business rule |
|---|---|---|
| `Booking` | rezerwacja / blokada / serwis | One row on the calendar timeline for one vehicle. `type`: `reservation` (paying customer), `block` (manual hold), `service` (workshop, not rentable). All three share one axis so a car cannot be double-booked across types. |
| `BookingStatus` | status rezerwacji | `tentative` → `confirmed` → `active` → `completed`, or `cancelled` at any point. Sending a confirmation e-mail auto-flips `tentative` → `confirmed`. |
| overlap / `hasOverlap` | nakładanie się terminów | Half-open interval check `[start, end)`: the return day of one booking equals the pickup day of the next is **not** a conflict (same-day turnaround is normal for this business). Enforced twice — server re-check in `db.ts`/`book-public.ts` and a Postgres exclusion constraint `bookings_no_overlap` (belt and suspenders). |
| `rentalDays` | liczba dni najmu | `differenceInCalendarDays(end, start)` — the return date itself is **not** billed (16→26 = 10 days, not 11). Pickup/return **time** does not change the day count. Real billing bug in production history; regression-tested in `src/lib/invoice.test.ts`. |
| `dailyRate` / `total` | stawka / suma | `dailyRate` = net ISK per day; `total` = gross total (what the customer owes) — the two are entered independently in the UI, not derived, because historical/imported bookings don't always have a clean `rate × days`. |
| `vatRate` | stawka VAT (VSK) | Percent, e.g. `24` or `0`. **Defaults to 0 when absent** (`booking.vatRate ?? 0`) — old bookings and bookings created before this field existed must never be assigned a VAT rate they were never priced with. `invoiceAmounts()` derives net/VAT from gross only when `vatRate > 0`. |
| `deposit` | kaucja | Refundable hold taken at pickup, tracked as a plain amount on the booking; refund/deduction is currently a manual note, not a workflow state (`docs/ROADMAP.md`, module C). |
| `Contract` | umowa | The rental agreement, generated from the template in `contract.ts` and frozen as `content` (HTML snapshot) at creation/send time. **A signed contract's `content` is immutable** — later edits to `OWU`/the template text never retroactively change a contract a customer already signed. |
| `OWU` | Ogólne Warunki Umowy (terms & conditions) | The liability/exclusions clauses baked into `contract.ts` (§1–§9): off-road driving ban, water-crossing damage, wind-blown doors, driver-not-on-contract penalty, accident reporting window (12h), etc. Iceland-specific, PL+EN only today (no Icelandic text yet — regulation 840/2015 expects it; gap flagged, not resolved, in `CHANGELOG.md` 2026-07-31). |
| `signToken` / `sign_token` | token podpisu | One-time, 14-day-expiry token behind `/sign/[token]`; a contract is signed exactly once (idempotent — a second POST is rejected, not re-processed). |
| `BookingLink` | link rezerwacyjny (self-service) | A single-use, 60-minute-expiry public link (`/book/[token]`) that lets a customer submit a booking request for **one specific, pre-chosen vehicle** without an account. States: `awaiting_client → submitted → confirmed / changes_requested / rejected`, or `expired`. |
| `Invoice` | faktura | `number` format `RRRR/NNNN` (gap-free within a year), issued server-side with a `UNIQUE` constraint + retry, same pattern as contract numbering. `status`: `sent \| paid \| void`. |
| `paymentMethod` | metoda płatności | `revolut \| bank_isk \| bank_pl \| cash`. Bank account numbers are **never hardcoded** — they come from `NEXT_PUBLIC_BANK_*` env vars (public because the invoice legitimately shows them to the customer, but the repo itself must not carry real account numbers). |
| `paymentTerm` | termin płatności | `pickup` (due before handover) or `return` (due at drop-off) — chosen per invoice, drives the label shown to the customer. |
| `Customer.suspect` / `is_suspect` | klient oznaczony | Manual flag an admin sets on a problem customer; surfaced in the UI as a warning, not an automatic block. |
| `isCompanyCustomer` | klient firmowy | A customer counts as a company when `companyName` is set. The renter of record is then the **company** (billed party); `name` is the actual driver — shown as `"Company — Driver"` everywhere (calendar, invoice, contract) so company bookings stay searchable by company name. |
| `nowIceland` / `todayISO` | "teraz" po islandzku | Iceland has no DST and runs UTC year-round. All "today" logic must go through these helpers, never bare `new Date()`, or the calendar/dashboard drift by a day for anyone browsing from a different timezone (e.g. Poland, UTC+1/+2). |
| checklist (`customer_checklists`) | checklista wydania | Per-customer key/value done-flags shown at vehicle handover (documents checked, deposit taken, etc.) — not a fixed schema column set, so new checklist items don't need a migration. |
| kílómetragjald | opłata za kilometry | Icelandic per-km road-use charge (Law 100/2025); odometer start/end are recorded per booking specifically to support this reporting/settlement need (`docs/ROADMAP.md`, item B5). |
| `Company` / `COMPANY` (`src/lib/company.ts`) | wynajmujący (podmiot) | The legal entity that rents the car out — the landlord block on the agreement and the seller on the invoice. Not to be confused with `isCompanyCustomer`, which is about the customer being a company. More than one profile can exist (the contract and invoice screens let you pick); `COMPANY` is the default, first on the list. |
